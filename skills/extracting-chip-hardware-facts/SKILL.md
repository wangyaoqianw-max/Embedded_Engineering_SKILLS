# Extracting Chip Hardware Facts

按当前项目任务，从已有芯片和板级资料中建立可追溯的工程事实，并总结相关硬件功能的使用条件。只整理与当前任务有关的内容，不摘要整本手册。

## 适用范围

- 需要为具体项目确认引脚、复用功能、外设、时钟、DMA、中断、电气限制、板级连线或芯片勘误。
- 资料盘点、查找或下载缺项使用 `embedded-resource-acquisition`。
- 纯概念解释、固件实现、构建、烧录和调试不由本 Skill 接管。

## 工作流程

1. 确定目标项目根目录：优先使用用户指定的项目；否则从当前工作目录向上检查项目标记、`AGENTS.md`、README 和仓库根。若当前目录位于嵌套工程内，结合当前任务和最近的项目标记确定实际项目，不把任意子目录当作根目录。读取适用的项目规则。
2. 检查项目 README、相关配置和已有硬件资料，同时识别现有硬件分析文档的目录、命名和格式约定。记录开发任务、完整芯片型号/封装/修订版、板卡版本；未知信息先标记，只有影响结论时才询问。不要无目标地扫描无关目录。
3. 把开发任务拆成待确认问题，例如实际引脚和网络、AF、电气属性、外设时钟、DMA 请求与映射、IRQ、操作顺序和相关 Errata。
4. 按问题选择证据来源，并检查相互依赖的章节：

   | 资料 | 用来确认 | 不用来单独确认 |
   |---|---|---|
   | 开发板原理图 | MCU 与外围器件的实际网络、供电、时钟、上拉下拉、连接器和控制脚 | 芯片是否支持该引脚功能或外设机制 |
   | Datasheet | 精确型号和封装的 Pinout、AF、引脚电气属性、额定范围 | 外设寄存器行为和完整操作顺序 |
   | Reference Manual | 外设机制、RCC 时钟、DMA 请求/映射、IRQ 条件、状态位和操作顺序 | 该开发板的实际接线 |
   | Errata | 精确型号/芯片修订版下的问题、触发条件、影响和 workaround | 未匹配修订版的无条件结论 |
   | 其他厂商资料 | 任务确实需要时补查 Programming Manual、应用笔记、板卡手册或 HAL/LL 文档 | 替代上述来源对硬件事实的核对 |

5. 先从原理图确认板级实际连接，再用 Datasheet 验证封装和引脚能力；随后查 Reference Manual 中外设及相关时钟、DMA、IRQ 章节。按精确型号和修订版检查 Errata；若修订版未知，将其适用性标为未确认，不把特定修订版 workaround 当作通用要求。
6. 若原理图不存在或目标区域看不清，说明哪项板级事实无法核实，请用户人工提供放大的局部截图。截图要看清 MCU 目标引脚名、网络标号、相关器件引脚及连接器；RS485 场景还要包含收发器 DI/RO、DE/RE、A/B 和接口网络。原理图本身不可用时，询问用户能否从其可用资料中截取该区域；拿不到时保持接线结论未确认。继续整理其他已有资料能够确认的芯片事实。
7. 对照资料检查冲突和依赖。不得因为某引脚支持目标 AF 就声称它已连到开发板外围器件，也不得按同系列经验填补型号、修订版、引脚或电气限制。
8. 给每项影响开发的结论标记状态：

   - `CONFIRMED`：来源直接支持，适用型号/封装/版本相符。
   - `INFERRED`：由已确认事实推导；同时写明前提和推导链。
   - `UNRESOLVED`：缺少资料、硬件身份不全或证据不足。
   - `CONFLICT`：可信来源之间不一致；列出两侧证据，不擅自裁定。

## Markdown 报告

每次完成项目硬件资料整理都要生成 Markdown 报告，即使用户没有单独要求保存文件。按以下顺序确定位置：

1. 使用用户明确指定的输出路径。
2. 否则遵循项目 `AGENTS.md`、README 中的输出规则，并沿用已有硬件分析文档的位置、命名和格式约定。
3. 如果项目没有约定，使用 `<project-root>/docs/hardware-analysis/YYYY-MM-DD-<chip>-<feature>.md`。

从嵌套工作目录识别项目根目录；除非用户明确指定其他位置，报告默认放在目标项目内。用户明确指定路径时遵循第 1 条，即使该路径位于项目根目录之外。若无法可靠判断目标项目或根目录，先询问用户要分析的项目/资料位置；只有用户未指定输出路径时，才需要同时确认保存位置。不要写入猜测的目录。创建所需的输出子目录。目标文件已存在时绝不覆盖，按项目命名风格添加不冲突的后缀（如 `-2`）。保存后回读确认文件存在且内容完整。

报告内容按项目现有风格组织；没有格式约定时至少包含：

1. 任务和适用硬件身份。
2. 工程事实表：问题、结论、状态、对使用的影响、来源定位。
3. 实际板级连接与芯片能力的对应关系；若原理图缺失或不可读，列出所需局部截图内容。
4. 与任务相关的使用步骤、时钟/DMA/IRQ/电气依赖及 Errata 条件。
5. 风险、冲突、缺失资料和待确认项。

关键结论应定位到文档名及版本/修订、章节/表格/页码；原理图应尽量包含 Sheet、网络名或器件标号。资料未提供页码或无法定位时如实说明，不编造出处。写入后，最终回复给出可点击的绝对路径链接；报告保存在项目内时，同时给出项目相对路径。若目标项目或根目录无法识别，先询问项目身份或资料位置；若用户未指定输出路径，也应确认保存位置。
