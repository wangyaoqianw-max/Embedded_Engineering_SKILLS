# 源码阅读失败案例

记录实际观察到的遗漏、误判或越界行为；不要把一次案例直接提升为全局规则。每条案例按下列状态推进：

- `Observed`：观察到一次行为。
- `Candidate Rule`：根因分析后形成待验证规则。
- `Validated`：已在多个实际场景验证。
- `Integrated`：稳定规则已进入 `SKILL.md` 或输出合同。
- `Rejected`：确认属于项目特例或不应形成规则。

## 案例模板

```markdown
## FC-NNN - <简短问题标题>

- 状态：Observed
- 场景：
- 预期行为：
- 实际行为：
- 影响：
- 根因：已证实 / 假设 / 未知，并说明证据
- 修正或候选规则：
- 验证范围：
- 是否进入 Skill：否 / 候选 / 是 / 已拒绝
```

## FC-001 - 阅读笔记缺少可定位证据和阅读顺序

- 状态：Observed
- 场景：`tests/embedded-code-reader/scenario.md` 中的 UART DMA 接收阅读任务。
- 预期行为：按本 Skill 的文档设计，关键结论提供路径和行号，并给出建议源码阅读顺序。
- 实际行为：无 Skill 基线覆盖了主流程、回调、状态和未知项，但没有行号证据或建议阅读顺序；见 `tests/embedded-code-reader/baseline-output.md`。
- 影响：读者需要重新搜索才能核对结论或从文档继续阅读源码。
- 根因：未证实；基线执行时没有可复用的输出合同，可能是原因之一。
- 修正或候选规则：输出模板为证据和建议阅读顺序保留必需位置。
- 验证范围：一个合成 UART DMA fixture；尚未跨项目验证。
- 是否进入 Skill：部分进入输出合同，尚未验证为普遍模型失败。
