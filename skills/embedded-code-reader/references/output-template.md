# 源码阅读笔记模板

按目标范围选择报告密度。小范围分析可合并过短或重复的章节；只有配置、初始化、数据/状态流或模块关系本身需要解释时才单独展开。每个关键结论都要能回到具体源码证据；结尾保留按阅读依赖排序的文件/符号清单。

```markdown
# <目标> 源码阅读笔记

## 阅读范围
- 目标：
- 已阅读范围：
- 未覆盖范围：
- 源码版本与分析日期：可获取时记录 Git 提交号和日期，否则省略或标为未知。

## 流程概览
用简短步骤概括入口到主要消费者的路径，并在关键步骤附源码证据。

## 文件与符号索引
|职责|文件 / 符号|证据|
|---|---|---|

## 配置与初始化
配置来源、条件分支、初始化入口及当前可确认的选择。

## 运行时调用链
按发生顺序区分直接调用、ISR、回调/函数指针和 RTOS 唤醒关系。

## 数据流与状态变化
说明关键数据从哪里产生、如何传递、由谁消费；列出相关状态及转换。若状态跨复位或保存在非易失存储中，说明启动分支、提交顺序和中断后的恢复路径，并区分源码可证明行为与未经硬件验证的持久性。

## 模块协作
概括目标涉及的模块、依赖方向和协作接口。

## 未确认事项
列出仅凭当前源码、配置或工程材料无法确认的行为。

## 建议阅读顺序
1. `path/file.c` — 入口或配置：理由
2. `path/other.c` — 实现或间接调用：理由
```

## 证据写法

- 采用仓库相对路径和核对过的行号，例如 `src/uart_service.c:42`。
- callback/function pointer 关系同时引用注册处和实际分发调用处。
- 条件编译路径引用宏定义和使用点；若工程配置无法确定活动分支，明确写成未确认。
- 跨文件调用、状态或数据关系引用足以证明关系两端的源码位置；同一结论不必在多个章节重复展开。
