# 嵌入式源码阅读

帮助开发者建立已有嵌入式工程中某个功能的可核对模型：入口在哪里、配置如何生效、运行时如何协作、数据和状态如何变化，以及应该按什么顺序阅读相关源码。

## 适用范围

- 用户要理解已有工程中的模块或功能，并希望得到源码阅读笔记。
- 用户关注启动/初始化、配置、直接或间接调用链、数据流、状态流或模块协作。

不用于实现或修改代码、构建、烧录、Debug、Code Review、架构设计或脱离具体工程的纯概念解释。遇到这些请求时按对应任务处理，不要顺带生成源码阅读文档。

## 输入和输出

- 分析目标是必需信息。若目标无法从请求中识别，先询问要分析的模块或功能，不要扫描整个仓库寻找目标。
- 分析范围可选。未指定时围绕当前工程中的目标逐步扩展，只读取解释该功能所需的文件。
- 输出目录可选。未指定时使用 `docs/code_reading/`；文件名用目标的简洁 snake_case 表示，并以 `_code_reading.md` 结尾。
- 若目标文档已存在，先确认它与当前目标相符，再更新该文档；不要创建 `_new`、`_final`、`_2` 等副本。目标或路径有歧义时先询问。

源码和工程配置只读。除用户指定的源码阅读 Markdown 文档外，不得修改目标工程中的其他文件；不运行构建、测试、烧录或调试，也不生成源码补丁。

## 阅读流程

按目标逐步扩展阅读范围，避免无目标地遍历或逐个阅读整个工程。

开始定位源码前，先检查目标工程根目录是否已有 `.codegraph/`。如果已有索引，在搜索或阅读源码前优先用可用的 `codegraph_explore` 查询目标符号、调用关系或数据流，并将目标工程路径传给 MCP 的 `projectPath` 参数；MCP 工具不可用时，在目标工程目录使用 `codegraph explore`。用返回的源码和行号核实候选关系，只补读 CodeGraph 未覆盖但结论所需的工程配置或其他文件。若没有索引，跳过 CodeGraph，继续定向阅读；不要自动运行 `codegraph init`。

1. 查看适用的项目指导（如 `AGENTS.md`）、README、目录结构、工程入口或相关项目说明，获取解释目标所需的最少上下文；将文档中的行为描述与源码和工程配置核对。
2. 搜索目标相关接口、类型、宏、实现和引用，先定位候选文件，再阅读相关实现。
3. 从启动入口和公开接口向下追踪初始化与运行路径；记录直接调用关系。
4. 检查相关配置的定义、默认值、覆盖来源和条件编译。只有在活动构建配置可确认时才断言某分支实际生效；否则并列说明候选分支或标为未知。
5. 对异步路径继续核对实际注册和分发关系，包括相关 ISR、中断服务例程、HAL/weak callback、函数指针、RTOS 通知或队列。仅凭符号引用不能断言运行时调用。
6. 沿生产者、传递机制到消费者追踪关键数据；追踪与目标有关的状态定义、赋值和转换。若状态跨复位或保存在非易失存储中，再追踪状态写入者、提交顺序、启动时读取/选择分支、破坏性操作前置条件，以及中断后的重试、恢复或回滚路径；硬件断电持久性仅凭源码不能确认。
7. 总结目标模块间的依赖和协作，并检查每项关键结论的源码证据。
8. 按 [输出模板](references/output-template.md) 写入阅读笔记。按目标范围裁剪章节，避免重复描述同一流程；证据引用和建议阅读顺序必须保留。

## 证据与边界

- 关键结论用仓库相对路径、行号和符号定位，例如 `src/uart_service.c:42`；核对行号后再写入文档。
- 分开陈述源码直接展示的事实、基于多处证据得出的调用/数据关系，以及当前材料无法确认的事项。
- 不把宏定义等同于生效配置，不把函数声明等同于实现，不把回调注册等同于已经发生的调用。
- 外部库、硬件行为、调度行为或构建选择未在可读材料中体现时，标为未知；不要凭经验补成项目事实。
- 目标流程已能由证据解释后停止扩展，避免把无关模块写进文档。

## 脚本边界

当前版本不附带脚本。后续只有在实际使用中反复出现稳定、确定性的证据收集步骤时才考虑脚本；脚本只收集符号位置、配置定义、注册关系等事实，由 Skill/Agent 解释运行含义。多个 Skill 共用的工具放入 `Embedded_Engineering_TOOLS`。
