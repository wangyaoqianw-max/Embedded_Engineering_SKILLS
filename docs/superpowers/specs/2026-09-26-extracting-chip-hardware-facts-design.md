# 芯片硬件事实提取 Skill 设计

## 目标

为具体嵌入式项目，从已有芯片和板级硬件资料中提取与当前开发任务直接相关的事实，并说明使用这些硬件功能时必须满足的映射、时钟、DMA、中断、电气和勘误约束。产物是一份保存到项目合适位置的 Markdown 工程事实整理，不是整本手册摘要。

## 范围与边界

- 输入是当前项目、开发任务、已归档或用户提供的硬件资料，以及可读取的项目配置。型号、封装、芯片版本、板卡修订版等信息不明时标为未知；仅在它们阻断结论时询问。
- 本 Skill 读取和分析现有资料。发现资料缺失时列出缺项并交接给 `embedded-resource-acquisition`；不下载资料、不转换 PDF、不修改网络设置。
- 本 Skill 说明硬件能力和使用约束，不实现固件、不构建、不烧录、不调试。
- 每次完成整理后都生成 Markdown 文件；从当前工作目录或用户指定的目标项目识别项目根目录。
- 用户明确指定的报告路径优先；未指定路径时服从项目 `AGENTS.md` / README 中的说明和现有硬件分析文档位置及命名约定，并默认保存在项目内。没有既有约定时，保存到 `<project-root>/docs/hardware-analysis/`，文件名包含日期、芯片和目标功能；不覆盖已有文件。
- 无法可靠识别项目根目录时，先询问目标项目身份或资料位置；仅在用户未指定输出路径时一并确认保存位置，不向不确定的工作目录写入。

## 资料职责

| 资料 | 用于确认 | 不单独据此确认 |
|---|---|---|
| 开发板原理图 | MCU 与外围器件的实际网络连接、供电、上拉下拉、晶振、连接器和控制脚 | 芯片是否支持某项引脚功能或外设机制 |
| Datasheet | 精确封装的引脚、Pin/AF 映射、电气属性、额定范围和器件能力 | 外设寄存器行为和完整初始化机制 |
| Reference Manual | 外设行为、时钟关系、DMA 请求/映射、IRQ 条件、寄存器与操作顺序 | 当前板卡实际连线 |
| Errata | 指定器件/修订版下的已知问题、触发条件、影响和 workaround | 未匹配修订版的无条件结论 |
| 其他厂商资料 | 仅在任务需要时补充，如 Programming Manual、应用笔记、板卡手册或 HAL/LL 说明 | 替代上述资料对硬件事实的确认 |

## 工作流

1. 从当前工作目录或用户指定的目标项目识别项目根目录，读取适用的 `AGENTS.md`、README、相关配置和已有硬件资料。确认任务、芯片完整型号/封装/版本、板卡版本及文档输出约定；不做无目标的全盘扫描。
2. 把任务拆成会影响开发的待确认问题，例如 Pin/AF、实际网络、时钟、DMA、IRQ、电气限制、初始化依赖和相关 Errata。
3. 优先从原理图确认板级实际连接，再用 Datasheet 验证芯片封装与引脚能力，用 Reference Manual 查外设机制，并按精确型号/修订版检查 Errata。识别到 DMA、时钟或 IRQ 依赖时，继续查相关章节。
4. 若原理图缺失或目标区域无法辨读，说明缺少哪项板级事实并请求人工提供目标区域的局部截图。截图请求指出需要看清的 MCU 引脚名、网络标号及相关器件/连接器；对 RS485 等场景还应包含 DE/RE、收发器和接口连接。原理图相关结论保持 `UNRESOLVED`，同时继续整理其他可由现有资料确认的事实。
5. 对照资料解决冲突。原理图与 Datasheet 不一致时标记 `CONFLICT`；基于明确前提推导出的结论标记 `INFERRED` 并写出推导；来源直接支持的结论标记 `CONFIRMED`；证据不足的结论标记 `UNRESOLVED`。不得以系列经验补齐缺失事实。
6. 按当前任务总结可执行的硬件使用约束和依赖顺序，并列出风险、冲突、缺失资料和待用户补充项。

## 输出合同

1. 任务与适用硬件身份。
2. 与任务相关的工程事实表：问题、结论、状态、对使用/实现的影响、来源定位。
3. 板级连接和芯片能力的对应关系；没有足够原理图证据时明确请求的局部截图内容。
4. 使用步骤或初始化依赖，以及电气、时钟、DMA、IRQ、Errata 限制中与任务相关的部分。
5. 冲突、风险、缺失资料和待确认项。

完成后将整理结果写成 Markdown 文件。用户明确指定路径时写到该位置；否则按项目规则和既有分析文档约定选择项目内路径，没有约定时使用 `<project-root>/docs/hardware-analysis/YYYY-MM-DD-<chip>-<feature>.md`。若目标文件已存在，选择不冲突的文件名而不覆盖。最终回复给出可点击的绝对路径链接；报告保存在项目内时，同时给出项目相对路径。

来源定位尽可能包含文件名、文档版本/修订、章节/表格/页码；原理图还应给出 Sheet、网络或器件标号。无法定位的来源不得伪造页码或章节。

## 验证

- 无 Skill 基线使用含引脚映射、外设/DMA 依赖、Errata 条目且缺少或无法辨认原理图目标区域的任务场景，观察是否会无证据地认定实际板级连线、忽略跨文档依赖或不请求局部截图；同时观察是否按项目工作目录约定创建 Markdown 报告。
- 使用 Skill 重跑相同场景，检查来源职责、结论状态、交叉核对、截图请求、项目根目录识别、报告落盘位置和可执行使用总结。
- 回归检查显式调用、隐式的项目硬件资料提取请求，以及纯概念解释、资料下载归档、固件实现/调试等边界。
