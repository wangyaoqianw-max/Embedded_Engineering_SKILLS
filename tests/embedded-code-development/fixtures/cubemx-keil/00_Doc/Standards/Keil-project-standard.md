# Fixture Keil project and build standard

This standard is authoritative for the sanitized project in this fixture only.

## Project inputs and outputs

- Board.ioc and MDK-ARM/Board.uvprojx are project inputs.
- Build products are disposable only after confirming they are inside the configured build output directory.
- Never treat project inputs, source files, or local standards as generated build products.

## Targets and output paths

Inspect every Target in Board.uvprojx. The expected target names and output paths, relative to MDK-ARM/Board.uvprojx, are:

| Target | Objects | Listings |
| --- | --- | --- |
| Debug | ../build/keil-debug/objects/ | ../build/keil-debug/listings/ |
| Release | ../build/keil-release/objects/ | ../build/keil-release/listings/ |

Do not replace these target-specific paths with a shared or guessed default.

Each Target owns its Groups. Every source required by both configurations must appear in the relevant Group under both Debug and Release.

## Build order

For a project freshly generated by CubeMX, inspect both Targets and these output paths before the first code edit. If a Keil backend is available, clean and build each Target before source changes, then preserve the observed result as the baseline. Do not clean any directory until its exact path and contents have been checked.

After implementation, build the affected Targets again and compare the result with the recorded baseline. Report unavailable builds as unverified.

## Failure evidence

Keep compiler diagnostics tied to their source file and line. An object-file write or I/O error without a reproducible source diagnostic is output/environment evidence; check the configured output path and environment before considering source changes.
